# 道路規制・仮置場の状態確認におけるAI呼び出し削減 — 実装計画

作成日: 2026-11-19

## 1. 現象と原因

`disaster-intelligence:verify-roads` / `verify-waste-sites` は、実行のたびに次を行っている。

1. 復旧・受入状況の情報源（最大15/12件）を取得する。
2. 全候補（解除済み・終了済みを含む）と、全情報源の本文（道路6万文字、仮置場12万文字）を1回のプロンプトにまとめてAIへ送る。
3. AI判定の後で、キーワード（「解除」「開通」「受入終了」等）による判定を補完として使う。

この構造には次の無駄がある。

| 原因 | 結果 |
| --- | --- |
| 情報源に候補の路線名・仮置場名が1件も載っていなくてもAIを呼ぶ | AIは `unknown` を返すだけ。解除情報が出ない間、毎回同じ費用がかかる |
| 情報源の内容が前回と同じでもAIを呼ぶ | 同じ入力で同じ `unknown` を得るためにAIを使い続ける |
| 本文全体を送る | トークンが多い。6万/12万文字で切り捨てるため、後半の解除記載がAIに届かないこともある |
| 解除済み（道路 `open`）・終了済み（仮置場 `closed`）も毎回候補に入る | 判定が確定した候補にもAIを使う |
| 「○号の通行止めを解除しました」のように機械的に確定できる記載もAI判定に回る | 不要なAI呼び出し |

## 2. 検討した対策と選定

| 案 | 効果 | 課題 | 採否 |
| --- | --- | --- | --- |
| A. 実行頻度をさらに下げる | 呼び出し回数は減る | 解除の反映が遅れる。無駄な呼び出しの比率は変わらない | 不採用 |
| B. 情報源の本文ハッシュが同じならスキップ | 変化のない日は0回 | 更新日時や他路線の記載が変わるだけで全件再判定になる | 部分採用（候補単位に細分化） |
| C. AIを使わずキーワードのみで判定 | AI費用ゼロ | 「解除見込み未定」などの誤判定。精度低下 | 不採用 |
| **D. AI前段のゲート（確定判定 → 記載有無 → 候補単位の変化検知 → 抜粋送信）** | 情報に変化がある候補だけをAIへ送る。送信量も抜粋に絞る | 実装量は中程度 | **採用** |

D は B と C の長所を組み合わせ、精度を落とさずにAI呼び出しを「新しい情報が出た候補」に限定できるため採用する。

## 3. 実装内容

### 3.1 判定フロー（道路・仮置場共通）

```
候補ごとに:
  ① 確定済み（道路 open / 仮置場 closed）        → 対象外（AIなし）
  ② 同一文内に確定表現あり（否定・予定表現なし） → キーワードで確定（AIなし）
  ③ どの情報源にも候補名の記載なし               → unknown（AIなし）
  ④ 候補名周辺の抜粋が前回AI判定時と同一         → 前回のAI結果を再利用（AIなし）
  ⑤ 上記以外                                     → AIへ送る（抜粋のみ）
AI失敗・AIが候補を省略 → 従来の広い範囲のキーワード判定で補完
```

- ② 確定表現
  - 道路: 候補名の後ろ、同じ文・行の中に「解除」「開通」「通行止めなし」「規制なし」「通行可」。
    「見込」「予定」「未定」「目途」「検討」「一部」等を含む場合は確定しない。次の路線名（国道・県道・市道等）が出た位置で文を打ち切り、別路線の解除を誤って拾わない。
  - 仮置場: 候補名の後ろ、同じ文・行の中に「受入（受付）を終了しました」「閉鎖しました」等の完了形。「予定」「見込」等を含む場合は確定しない。
- ④ 変化検知
  - 候補の内容（路線名・区間・規制種別・事由／名称・状態・終了日・品目）と、候補名周辺の抜粋からSHA-256の指紋を作り、AI結果とともにキャッシュする。
  - ページの更新日や他路線の記載だけが変わっても、その候補の抜粋が同じなら再判定しない。
  - キャッシュの有効期限（既定7日）を過ぎたら、内容が同じでも1回だけ再判定する。
  - AI呼び出しが失敗した場合はキャッシュしない（次回に再試行する）。
- ⑤ 抜粋送信
  - 各情報源の冒頭200文字（タイトル・更新日の確認用）と、候補名の前150文字・後400文字の範囲だけを送る。重なる範囲は結合する。
  - 全体の上限は4万文字（`DISASTER_STATUS_CHECK_MAX_CHARS`）。

### 3.2 本文の正規化

全角英数字・全角スペースを半角化し、空白を除去してから照合する。これまで「国道１号」（全角）と「国道1号」が一致しなかった問題も解消する。

### 3.3 変更ファイル

| ファイル | 変更 |
| --- | --- |
| `app/Services/DisasterIntelligence/StatusCheckGate.php` | 新規。正規化・抜粋・確定判定・指紋キャッシュ |
| `app/Services/DisasterIntelligence/RoadRecoveryVerifier.php` | ゲートを通してAI対象を絞る。`$fresh` 引数を追加 |
| `app/Services/DisasterIntelligence/WasteSiteStatusVerifier.php` | 同上 |
| `app/Console/Commands/VerifyRoadRecovery.php` | 候補に現在の状態を渡す。`--fresh` オプション追加 |
| `app/Console/Commands/VerifyWasteSiteStatus.php` | `--fresh` オプション追加 |
| `resources/prompts/road_recovery_check.txt` / `waste_status_check.txt` | 抜粋入力であることを明記。「一覧にない＝解除」判定を削除 |
| `config/disaster-intelligence.php`、`.env*.example` | `status_check` 設定を追加 |

### 3.4 運用

- 実行ログに `候補数 / 確定済み / キーワード確定 / 記載なし / キャッシュ再利用 / AI送信候補数 / AI呼び出し回数` を出力する（`道路の復旧確認ゲート` / `仮置場の受入確認ゲート`）。
- キャッシュを無視して再判定したいときは `--fresh` を付ける。

### 3.5 仕様変更（許容する影響）

- 抜粋のみを送るため、AIによる「完全な一覧に記載がない＝解除」判定は行わない。一覧形式の情報源は熊本県の交通規制JSON取込（AI不使用）で対応している。
- 解除済みの道路・受入終了の仮置場は再確認しない。再開が疑われる場合は、データを修正するか、個別に確認する。

## 4. テスト・検証項目

### 4.1 自動テスト（PHPUnit）

| No | 観点 | 期待結果 |
| --- | --- | --- |
| T1 | AI判定結果の正規化（既存） | 抜粋経由でもstatus・出典URL・根拠が正しい |
| T2 | AI失敗時のキーワード補完（既存） | `open` と出典URLを返す |
| T3 | 「解除し、全面開通しました」（既存） | AIを呼ばずに `open` |
| T4 | 確定表現あり（道路） | AIへのリクエスト0件で `open` |

| T8 | 2回目の実行で抜粋が同じ | 2回目はAI 0件で前回結果を返す |
| T9 | 2回目に候補周辺の記載が変化 | AIを再度呼ぶ |
| T10 | 他候補・更新日だけが変化 | 変化のない候補はAIへ送らない |
| T11 | `$fresh = true` | キャッシュを無視してAIを呼ぶ |
| T12 | AI失敗時 | キャッシュしない。次回は再びAIを呼ぶ |
| T13 | 解除済み道路（status=open） | 結果に含めず、AIも呼ばない |
| T14 | 全角「国道１号」 | 半角候補と一致する |
| T15 | AIへ送る本文 | 候補周辺の抜粋のみ（無関係な長文を含まない） |
| W1〜W6 | 仮置場で T4/T5/T7/T8/T13 相当と既存テスト | 同様 |
